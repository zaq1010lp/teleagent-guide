# 1.9 多模型切换与适配

## 本章目标

理解 TeleAgent 的多模型架构，学会根据任务类型选择最合适的模型，掌握个人版与企业版模型管理的差异，优化 Token 使用成本。

## 1.9.1 为什么需要多模型

不同大语言模型在能力侧重上各有千秋：

| 能力维度 | 说明 |
| --- | --- |
| **推理深度** | 复杂逻辑分析、多步推理任务需要更强推理能力的模型 |
| **生成质量** | 文档撰写、PPT 制作需要语言表达优秀的模型 |
| **响应速度** | 简单问答、快速摘要等场景优先选择轻量高速模型 |
| **成本消耗** | Token 单价因模型而异，日常任务用轻量模型可大幅降低成本 |
| **领域适配** | 部分模型在法律、医疗、金融等垂直领域有专门优化 |

如果绑定单一模型，你只能在"万能但贵"和"便宜但弱"之间二选一。TeleAgent 的多模型架构让你**按需选模**——简单任务用轻量模型省 Token，复杂任务切到强模型保质量，实现效果与成本的最优平衡。

## 1.9.2 个人版的模型管理

### 选择默认模型

在「设置 → 模型配置」中，你可以为每个工作空间指定默认使用的大语言模型。不同模型在速度、能力和 Token 消耗上各有侧重，可根据任务类型灵活切换。

```
设置 → 模型配置 → 选择默认模型
```

切换模型后，当前工作空间后续所有新任务将使用新选定的模型。已有任务的上下文不受影响。

### 什么时候需要手动切换

| 场景 | 推荐策略 |
| --- | --- |
| 日常文件整理、简单摘要 | 使用默认轻量模型即可 |
| 复杂合同审核、深度调研 | 切换到推理能力更强的模型 |
| 生成 PPT、长文档撰写 | 切换到生成质量更高的模型 |
| 批量处理大量文件 | 使用速度快的模型，缩短等待时间 |

::: tip 省钱技巧
日常办公大部分任务用默认模型即可。只有遇到高难度推理或高质量生成需求时，再临时切换到更强模型，用完切回来。这样既能保证工作质量，又能控制 Token 消耗。
:::

### Token 使用统计

在1.3我们已介绍过数据统计功能，这里补充与模型优化相关的用法：

- **模型维度筛选**：按模型查看 Token 消耗分布。如果你发现某个高价模型占比很高，说明日常任务可能过度使用了强模型，可以调整策略。
- **历史趋势**：观察 Token 用量变化趋势，判断当前使用策略是否合理。

> **Token 速算**：一个中文字符约等于 1~2 个 Token，一个英文单词约等于 1~3 个 Token。具体消耗取决于任务复杂度和模型类型。

## 1.9.3 企业版的模型管理

企业版在个人版的基础上，增加了**管理员统一管控**能力，确保模型资源在企业内部合理分配。

### 模型配置（平台管理员）

平台管理员负责对接上游模型服务，维护模型配置：

| 配置项 | 说明 |
| --- | --- |
| 配置名称 | 便于识别的名称，如"星辰大模型-生产" |
| Chat Completions 地址 | 模型服务的完整 API 地址 |
| API Key | 模型服务的访问密钥 |
| 可调用模型列表 | 支持配置多个模型编码和名称 |

平台可维护多条模型配置，但同一时间仅一条生效。管理员可随时查看详情、编辑、切换生效状态或删除配置。

### 客户端配置（平台管理员）

配置好上游模型服务后，管理员还需设置**用户端可使用的模型列表**：

- 从当前生效的模型配置中，选择哪些模型对用户可见
- 用户只能从管理员开放的模型中选择使用
- 管理员可随时添加或移除可用模型

这一机制确保企业用户使用的模型都经过管理员审核，避免随意调用未经授权的模型。

### MaaS 平台

#### 模型管理

- **模型广场**：浏览所有已上架模型，查看模型详情和能力描述，帮助用户快速定位适合业务需求的模型
- **模型上架**：将新模型注册到平台，配置模型参数，管理模型的多版本发布和切换
- **版本可追溯**：已发布模型版本不可覆盖，确保每次迭代都有据可查

#### 资源管控

| 功能 | 说明 |
| --- | --- |
| **API Key 管理** | 为不同应用和用户分配独立的访问凭证，配置模型访问权限和调用限制 |
| **配额管理** | 设置模型调用的配额上限，实时监控各租户的使用量与趋势 |

配额管理支持自然日、自然周、自然月三种计费周期。平台管理员为每个租户设置 Token 上限，租户管理员再为租户内每个用户分配额度，实现精细化资源管理。

#### 运营监控

- **数据看板**：查看平台 Token 使用量和调用统计，为资源规划和成本核算提供依据
- **日志管理**：查看模型 API 调用详细日志，便于问题排查
- **消息通知**：配额用尽、服务异常等关键场景自动触发告警

#### 智能调度

传统多模型架构下，管理员需要手动指定每个任务用哪个模型，运维负担重。MaaS 平台的智能调度能力解决这一痛点：

- **智能路由**：根据模型能力、负载状况和响应延迟，自动选择最优模型实例处理请求
- **负载均衡**：多模型间自动分配流量，避免单点过载，保障服务高可用和最优响应时间

::: tip 智能调度的价值
假设企业部署了 3 个模型实例。某个周一上午任务高峰期，实例 A 负载满载，智能调度会自动将新请求路由到负载较低的实例 B 或 C，用户完全无感知。如果没有这个能力，高峰期请求堆积在单实例上，会导致任务超时甚至失败。
:::

## 1.9.4 模型选择实操

### 个人版：按任务选模型

以下是几种典型任务的模型选择建议：

| 任务类型 | 模型侧重 | 选择建议 |
| --- | --- | --- |
| 文件归类、重命名 | 基础文本理解 | 轻量模型，速度快、成本低 |
| 数据清洗、表格整理 | 代码执行+数据处理 | 支持代码执行的模型 |
| 合同审核、风险评估 | 深度推理+法律知识 | 推理能力最强的模型 |
| 经营分析报告撰写 | 长文本生成+逻辑组织 | 生成质量高的模型 |
| PPT 制作 | 结构化输出+创意 | 综合能力均衡的模型 |
| 深度调研 | 多轮检索+综合分析 | 推理+生成都强的模型 |

### 企业版：管理员视角的模型规划

企业管理员在规划模型资源时，需要从全局视角考虑：

1. **模型组合**：配置至少两种模型——一种轻量快速型用于日常任务，一种强力推理型用于复杂任务
2. **额度分配**：按部门或用户角色分配 Token 额度。高频用户适当增加额度，低频用户适度控制
3. **成本监控**：定期查看数据看板，分析各租户和模型的 Token 消耗分布，优化配置策略
4. **弹性扩容**：业务高峰期前评估模型算力是否充足，必要时增加模型实例

## 1.9.5 常见问题

| 问题 | 原因 | 解决方案 |
| --- | --- | --- |
| 切换模型后任务质量下降 | 新模型不适合当前任务类型 | 换回原模型，或在设置中尝试其他模型 |
| Token 消耗异常增多 | 可能误用了高成本模型 | 查看数据统计中的模型维度筛选，确认消耗来源 |
| 企业版用户看不到某个模型 | 管理员未在客户端配置中开放该模型 | 联系平台管理员在客户端配置中添加 |
| 模型调用报错 | API Key 失效或模型服务异常 | 个人版检查网络连接；企业版联系管理员检查模型配置 |
| 任务执行变慢 | 模型服务负载高 | 尝试切换到其他可用模型，或避开使用高峰期 |

## 1.9.6 本章小结

多模型是 TeleAgent 灵活性的核心体现。掌握模型选择策略，你可以在保证工作质量的同时显著降低使用成本：

- **个人版**：在工作空间设置中切换模型，简单任务用轻量模型，复杂任务用强模型
- **企业版**：管理员通过 MaaS 平台统一管控模型资源，智能调度自动优化流量分配
- **成本控制**：善用 Token 统计的模型维度筛选，持续监控和优化使用策略
